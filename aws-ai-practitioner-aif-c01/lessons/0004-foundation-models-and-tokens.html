Foundation Models and Tokens

Domain 1 is done. Now: what makes a generative-AI model different from the ML models in Lessons 1–3, and what is it actually doing when it "writes" an answer? Two ideas answer both questions: foundation models, and tokens.

From narrow models to foundation models

Every model in Lessons 1–3 was trained for one job: detect fraud, detect spam, predict churn. A foundation model is different — it's trained on a massive, broad slice of data (huge amounts of text, code, images) so that one model can then be adapted to many different tasks: writing, summarizing, translating, answering questions, drafting code — without training a new model from scratch for each one. That breadth is exactly why it's called a "foundation": you build many things on top of the same base.

Amazon Bedrock gives you access to several foundation models (Anthropic's Claude, Amazon's own Titan/Nova models, Meta's Llama, and others) through one AWS service, without you having to train or host the model yourself.

How it actually generates text: tokens

A foundation model doesn't see whole words the way you do. It breaks text into tokens — pieces that can be a whole word, part of a word, or punctuation — and then does one very repetitive thing: predict the single most likely next token, add it to the text, and repeat. That's it. A long, fluent-sounding answer is really thousands of "what's the next most likely token?" predictions chained together.

Example: the model doesn't store "certification" as one unit — it might see it as:

certification

Because each next token is chosen by probability, not by looking up a fixed rule, the same prompt can produce a slightly different answer each time — the model is probabilistic, not deterministic like a calculator. That single fact explains a lot of Domain 2 and Domain 4: it's also part of why foundation models can confidently generate something false (a "hallucination," which gets its own lesson soon).

The jargon, defined

Foundation model
A large model pre-trained on broad data, adaptable to many downstream tasks instead of just one.
Token
A chunk of text (word, sub-word, or punctuation) — the actual unit a foundation model reads and generates, one at a time.
Prompt
The input text you give the model to steer what it generates next.
Probabilistic generation
The model picks each next token based on likelihood, not a fixed rule — so the same prompt can yield different wording on different runs.
Why this matters for the exam: Domain 2 questions often describe a scenario and ask you to recognize "foundation model" vs. a narrow traditional ML model, or to explain why GenAI output varies or can be wrong. Both trace back to the two ideas on this page.

Practice with exam-style scenarios

1. A company wants one model it can reuse to translate documents, summarize reports, and draft emails, instead of training a separate model for each of those tasks. What kind of model should it use?
Reusing one broadly-trained model across many different tasks is the defining trait of a foundation model.
2. While a large language model is writing its response, what is it doing at each individual step?
Generation happens one token at a time, each chosen as the most likely next piece given everything so far.
3. An employee asks a foundation model the exact same question twice and gets two slightly different answers. What best explains this?
Each next token is chosen by likelihood, not a fixed lookup — so wording can vary run to run even for an identical prompt.

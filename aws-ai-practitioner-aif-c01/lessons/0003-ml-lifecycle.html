The Machine Learning Lifecycle

You now know what ML is and how it learns. This lesson goes slower than last time and defines every piece of jargon as it shows up, because the lifecycle is really just five plain-English ideas wearing exam-vocabulary costumes.

The story, in one paragraph

Imagine you want a model that predicts whether a customer will cancel their subscription. You start with a pile of past customer records where you already know who cancelled — that pile is your data. You clean it up, then split it into two stacks: a big stack to teach the model, and a small stack you hide away and don't show it. You show the model the big stack and let it find the pattern — that's training. Then you quiz it on the hidden stack it never saw — that's evaluation. If it does well, you let it start predicting on brand-new, real customers — that's deployment. Months later, customer behavior shifts (say, a new competitor shows up) and the model's guesses get worse even though nothing about the model itself changed — you only find out because you kept monitoring it.

The jargon, defined

Training data
The big stack: past examples the model is allowed to learn from, including the correct answer for each one (e.g. "this customer did cancel").
Test data (a.k.a. holdout data)
The small, hidden stack: examples the model never saw during training, used only to check if it actually learned the pattern or just memorized the training stack.
Overfitting
When a model memorizes the training stack so closely (including its noise and quirks) that it does great on training data but poorly on the hidden test data — it learned the exceptions instead of the pattern.
Inference
The act of a trained, deployed model making an actual prediction on new, real-world input. "Training" teaches it; "inference" is it doing its job afterward.
Drift
When the real world quietly stops looking like the training data (new customer behavior, new competitor, new season), so a model that was accurate at launch becomes less accurate over time — without anyone touching the model itself.

The five stages

1. Data collection & preparation
Gather the training data and clean it (missing values, duplicates, inconsistent formats). This is usually the most time-consuming stage.
2. Model training
The algorithm studies the training data and adjusts itself to capture the pattern in it.
3. Evaluation
Test the trained model on the hidden test data, to catch overfitting before it ever reaches a real customer.
4. Deployment
The model goes live and starts doing inference on real, incoming data.
5. Monitoring
Keep watching accuracy over time to catch drift, and loop back to stage 1 (fresh data, retraining) when it's caught.

Practice with exam-style scenarios

1. A company is building a model to predict equipment failure. Before releasing it, the team sets aside 20% of its labeled sensor data, never shows it to the model during training, and uses it afterward to check the model's accuracy. Which stage of the ML lifecycle does this describe?
This is the textbook definition of a holdout/test set: data the model never trained on, used specifically to measure real performance.
2. A retail company's product-recommendation model performed well at launch, but six months later shoppers complain that suggestions feel outdated, even though nobody changed the model's code. What best explains this?
The model itself didn't change — the world did. That gap between training-time data and real-world data is drift, and it's what monitoring exists to catch.
3. A model scores 99% accuracy on the data it trained on, but only 60% on new customer data it has never seen. What does this pattern most likely indicate?
A huge gap between training-set accuracy and unseen-data accuracy is the classic signature of overfitting: the model memorized specifics instead of learning the general pattern.
